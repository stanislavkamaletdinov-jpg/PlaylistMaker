# Playlist Maker

Учебное Android-приложение на Kotlin для поиска музыкальных треков через iTunes Search API. Позволяет просматривать результаты поиска, сохранять историю выбранных треков и переключать светлую и тёмную темы.

## Возможности

- Поиск песен по текстовому запросу. Поиск запускается кнопкой действия на экранной клавиатуре.
- Отображение названия трека, исполнителя, длительности и обложки.
- Сообщения об отсутствии результатов и ошибке загрузки, повтор неудачного запроса кнопкой «Обновить».
- Очистка поискового запроса и восстановление его текста при пересоздании экрана.
- История последних 10 выбранных треков с сохранением между запусками приложения.
- При повторном выборе трека с тем же `trackId` он перемещается в начало истории.
- Просмотр истории при фокусе на пустом поле поиска и очистка всей истории.
- Переключение светлой и тёмной темы с сохранением выбора. До первого выбора используется системная тема.
- Действия в настройках: поделиться ссылкой, открыть почтовое приложение для обращения в поддержку и открыть пользовательское соглашение.

Нажатие на трек добавляет его в историю. Воспроизведение музыки пока не реализовано.

## Архитектура и структура

Проект состоит из одного модуля `app`. Каждый основной экран представлен отдельной `Activity`. Логика поиска и управления интерфейсом находится в `SearchActivity`, хранение истории вынесено в `SearchHistory`, отображение строк списка — в адаптер и `ViewHolder`.

```text
app/src/main/
├── java/com/example/playlistmaker/
│   ├── MainActivity.kt          # Главное меню и восстановление темы
│   ├── SearchActivity.kt        # Поиск, состояния экрана и история
│   ├── SettingsActivity.kt      # Тема и действия в настройках
│   ├── MediaLibraryActivity.kt  # Заготовка экрана медиатеки
│   ├── ITunesApi.kt             # Retrofit-интерфейс API
│   ├── Track.kt                 # Модель трека
│   ├── TrackSearchResponse.kt   # Модель ответа поиска
│   ├── SearchHistory.kt         # Чтение и сохранение истории
│   ├── TrackAdapter.kt          # Адаптер списка треков
│   └── TrackViewHolder.kt       # Отображение данных трека
├── res/                        # Разметки, строки, темы и изображения
└── AndroidManifest.xml
```

## Требования

- Android Studio с поддержкой Android Gradle Plugin **9.4.0**.
- Совместимый с используемыми AGP и Gradle JDK; для настройки Gradle JDK можно использовать встроенный JDK совместимой версии Android Studio.
- Android SDK Platform **37** (`compileSdk` и `targetSdk` — 37).
- Устройство или эмулятор с **Android 10 (API 29)** или новее.
- Доступ к интернету для загрузки зависимостей, поиска треков и получения обложек.

В проекте используется Gradle Wrapper **9.6.0**. Уровень совместимости Java в модуле приложения — **11**; это настройка компиляции исходного кода, а не версия JDK для запуска Gradle.

## Запуск

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/stanislavkamaletdinov-jpg/PlaylistMaker.git
   ```

2. Откройте папку `PlaylistMaker` в Android Studio.
3. Установите Android SDK Platform 37 через SDK Manager, если она ещё не установлена.
4. Проверьте Gradle JDK в настройках Android Studio и выполните синхронизацию Gradle.
5. Выберите конфигурацию `app` и устройство с API 29 или выше.
6. Нажмите **Run**.

Дополнительные API-ключи в текущей реализации не настраиваются.

### Сборка из терминала

Выполните из корня проекта:

```bash
./gradlew assembleDebug
```

На Windows:

```powershell
.\gradlew.bat assembleDebug
```

Debug APK после успешной сборки находится в `app/build/outputs/apk/debug/app-debug.apk`.

## Источник данных

Приложение обращается к [iTunes Search API](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/index.html).

Базовый адрес: `https://itunes.apple.com/`.

Используемый запрос:

```http
GET /search?entity=song&term=<поисковый запрос>
```

Данные треков и обложки загружаются из внешнего сервиса. Для нового поиска требуется интернет; история выбранных треков хранится локально, но обложки могут требовать сетевой загрузки.

## Статус и дальнейшее развитие

Реализованы поиск, история выбранных треков и настройки темы. Экран медиатеки пока представляет собой пустую заготовку. Создание плейлистов, избранное и воспроизведение музыки отсутствуют.

Возможные направления развития:

- Добавить экран трека и воспроизведение аудиопревью.
- Реализовать медиатеку, избранное и плейлисты.
- Отделить работу с данными от логики экранов.
- Добавить тесты поиска, истории и сохранения настроек.

В проекте присутствуют шаблонные unit- и instrumented-тесты. Они не подтверждают корректность основных пользовательских сценариев.
